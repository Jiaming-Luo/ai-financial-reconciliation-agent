# 产品需求文档

[English](PRD.md) · [英文数据字典](data_dictionary.md)

## 1. 项目背景与业务痛点

医院检测费用取决于医院、检测科目、采集方式、业务类型和适用合同版本。人工核对容易漏掉调价、混淆混采计费单位，或误判分笔及跨月付款。出现差异后，追溯原始记录也需要时间。

## 2. 目标用户

- 核验检测费用并核对医院付款的财务复核人员。
- 核验业务数量、采集方式和报送金额的检测运营人员。
- 处理价格冲突并确认复核决定的合同及财务审批人员。

## 3. 产品目标与范围

使用模拟数据构建个人业务改进原型。MVP 应能展示适用合同、解释应收及付款差额，并提供原始凭据。覆盖单采、10 混 1、20 混 1、大筛查和个人自费检测。范围排除医院线上系统、真实患者及企业记录、银行集成、付款执行及多币种结算。

## 4. 用户使用场景

- 财务人员对比合同调价前后相邻两天的业务计费。
- 财务人员核对某月的两笔正常付款，其中一笔在次月支付。
- 审批人员处理合同冲突、缺失合同或无效数量，再确认受影响月份的结果。
- 复核人员追溯重复付款或报送金额错误，并记录处理决定。

## 5. 核心业务工作流

1. 导入并校验合同、业务和付款 CSV，保留源记录编号及原始字段用于追溯。
2. 对有效业务行按合同匹配键和包含起止日期的有效期寻找合同。匹配唯一且有效时校验计费单位并计算应收。
3. 识别重复付款，按医院和结算月汇总可纳入的付款及业务应收。有待解决的数据校验或定价问题时，挂起该结算组。
4. 展示异常证据及结算状态。人工记录决定或修正数据后重新计算。可选的 AI 辅助功能用于解释已有结果。

## 7. 财务计算与异常判断规则

- 合同匹配键包括医院、检测科目、采集方式和业务类型，以业务发生日期查找有效合同，包含起止日期。唯一有效合同提供价格和计费单位，业务单位须与其一致。数量按合同单位直接计费，混采数量也按原值使用。
- 使用 Decimal 或整数分。所有金额为 CNY，精确到分。单行应收等于计费数量乘以合同单价。报送金额与应收不同时标记 `PRICE_MISMATCH`。结算汇总仍采用合同金额，同时保留该行复核项。
- 无有效合同标记 `MISSING_CONTRACT`，多份有效合同标记 `CONTRACT_OVERLAP`。格式错误、字段超出允许范围，或唯一合同匹配后发现计费单位不一致，标记 `INVALID_DATA`。挂起受影响的结算组，输入未解决时暂不出具受影响的最终应收或差额。
- 按 `hospital_id` 和 `settlement_period` 归集。付款日期可以与结算月不同。同组内不同参考号的有效付款均可纳入汇总。
- 在整份付款文件中检查参考号。同一参考号的有效记录在医院、日期、结算月、金额和币种上均一致时，标记 `DUPLICATE_PAYMENT`，汇总时只计入字典序最小的付款编号，即使差额为零也保留复核标志。若明细冲突或其中存在无效记录，该参考号待核实，所涉及结算组均挂起，差额留空。
- 差额定义为应收减实付。金额可确定时，无付款为 `MISSING_PAYMENT`，存在有效付款且差额为正时为 `UNDERPAYMENT`，差额为负时为 `OVERPAYMENT`，差额为零时余额结果为 `MATCHED`。未找到付款记录不能作为认定逾期的依据。有效付款组无业务行时标记 `UNMATCHED_PAYMENT`。独立异常与余额结果可同时保留。结算组金额无法确定时，状态为 `REVIEW_REQUIRED`。

## 8. 非功能需求

- 相同输入产生一致结果，金额及异常可以追溯到源记录和适用合同编号。
- P0 支持离线处理至少与交付样例相同规模的数据。切换显示语言时，财务计算仍精确到分。
- 按约定字段定义显式校验 CSV，提供行级错误信息，保留原始输入。

## 9. 数据安全与人工复核

仅使用模拟输入，样例数据及 Git 仓库排除凭据。向复核人员展示原始记录、候选合同、计算金额和标记理由。复核人的身份、时间及决定理由与原始输入分开记录。AI 可归纳或解释证据，财务计算、复核决定和付款执行均由对应的确定性规则或人工权限控制。测试预期与规则执行隔离。

## 10. MVP 验收标准

- 按数据字典导入及校验三张源表，识别人为注入的无效行，其他结算组继续处理。
- 在调价边界两侧选用正确单价，按分复算各组余额。
- 正确处理分笔及跨月付款，从源 CSV 计算出全部十类样例结果，计算完成后再与预期 CSV 比对。
- 各异常均具备可复核证据。挂起未解决的结算组，并能保留人工处置的审计记录。

## 12. 首版假设及已知限制

每行业务只属于一个结算月，由来源提供。定价按业务发生日期。每笔付款只归入一家医院的一个结算月。医院编号来自源文件，首版没有独立医院主表。合同结束日期必填，计费数量为正整数，退款及贷项不纳入范围，差额容差为零分。首版假定付款来源使用全局唯一的交易参考号。原型不拆分跨月付款、不核销到单行业务、不单独处理税费和折扣，也不验证银行转账是否确实发生。
